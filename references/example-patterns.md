# Example Patterns

These examples are synthetic and should be used as style patterns only. Do not copy them blindly into a manuscript.

## Example 1: From variable list to system narrative

### Rough draft

There are M base stations and N users. Each base station has an edge server. Users generate tasks. The task has input data and CPU cycles. The base station can compute the task or send it to the cloud. Let x be the offloading variable.

### Polished pattern

We consider a mobile edge computing network consisting of M base stations and N mobile users. Each base station is co-located with an edge server, which can execute computation tasks generated by users within its coverage area. A task is characterized by its input size and required CPU cycles, capturing the communication and computation resources needed for its completion. Upon receiving a task, the associated base station either processes it locally at the edge or forwards it to the remote cloud. We use the decision variable x to indicate this offloading choice.

### Why it works

The revised version first builds the scene, then introduces task attributes, then explains the operational meaning of the decision variable.

## Example 2: Making assumptions feel justified

### Rough draft

We assume time is slotted. The requests in each slot are known. This is reasonable. The caching variable is updated in every slot.

### Polished pattern

We divide time into slots that match the update interval of caching decisions. At the beginning of each slot, the controller observes or predicts the service requests for the upcoming slot and then updates the caching configuration accordingly. This time-slotted model captures the fact that caching is adjusted at a slower time scale than individual task arrivals, while still allowing the system to react to temporal demand variations.

### Why it works

The assumption is tied to the operational time scale and its modeling consequence.

## Example 3: Introducing an equation

### Rough draft

The delay is D_i(t)=D_i^e(t)+D_i^c(t). D_i^e(t) is edge delay and D_i^c(t) is cloud delay. The objective minimizes delay.

### Polished pattern

Given an offloading decision in slot t, the latency experienced by user i consists of the edge-processing delay and the cloud-offloading delay. We therefore write the total delay as

```latex
D_i(t)=D_i^{\mathrm{e}}(t)+D_i^{\mathrm{c}}(t),
```

where D_i^{\mathrm{e}}(t) denotes the delay of tasks executed at the edge and D_i^{\mathrm{c}}(t) denotes the delay of tasks forwarded to the cloud. This decomposition makes the delay impact of the offloading decision explicit and will be used in the objective function.

### Why it works

The equation is motivated before it appears and interpreted after it appears.

## Example 5: Chinese-to-English polishing

### Chinese draft

考虑一个由多个边缘服务器和用户组成的系统，用户会产生不同类型的任务。由于边缘服务器的存储和计算资源有限，不可能缓存所有服务，所以需要决定缓存哪些服务以及任务如何卸载。

### Polished English pattern

We consider an edge-computing system composed of multiple edge servers and users, where users generate computation tasks associated with different service types. Since each edge server has limited storage and computing resources, it cannot host all services simultaneously. The system therefore needs to determine which services should be cached at the edge and how the resulting tasks should be offloaded for execution.

### Why it works

The translation keeps the original meaning but expresses the causal logic in natural academic English.
